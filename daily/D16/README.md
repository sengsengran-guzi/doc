## 1. 审计方法（多 agent 并行 — ultracode Workflow）

12 路 auditor 并行（5 业务域 + 5 横切 + 2 设计）→ 每路对抗式复核（试图证伪 + 校正 severity + 补 file:line）→ 汇总去重分级：

| # | 审计路 | 角度 |
|---|---|---|
| 1 | 拼豆 + 优惠券 | 产品 + 测试 |
| 2 | 回收 + 反向打款 | 产品 + 测试 + 资金 |
| 3 | 资讯 | 产品 + 测试 |
| 4 | 个人中心 | 产品 + 测试 |
| 5 | 扭蛋 | 产品 + 测试 + 公平 |
| 6 | 资金/支付/对账 | 测试（资金零容忍） |
| 7 | 权限/越权/多租户 | 测试（安全） |
| 8 | admin 功能完整性 | 产品（不评视觉） |
| 9 | 预购下线 + 系统底座 | 产品 |
| 10 | 数据/契约/状态机一致性 | 测试 |
| 11 | mp C 设计系统合规 | 设计 |
| 12 | mp 导航/可达性/交互态一致 | 设计 |

**审计纪律**：每条 finding 必须 READ 实际代码取证（file:line）；区分真缺陷 vs 外部前置（mock 支付/甲方素材/真机人验）；severity = blocker🔴(资金/数据/崩溃/越权) / pre-launch🟡(功能缺口/不一致) / post-launch🟢(优化)。
