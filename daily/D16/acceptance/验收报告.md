## 4. 🟠/🟡 新发现 Bug —— 一类系统性前端契约 bug（6 处，同根因）

### 根因（一句话）
后端部分 list 端点返回 **裸 `{total, rows}`（TableDataInfo）**，部分返回 **`{code, msg, data}`（R 信封）**；request.ts 拦截器统一返回响应体不再解包。前端 6 处把 TableDataInfo 列表当成 R 信封读 `res.data` / 解构 `{data}` / 当数组 `resp.map`，导致**列表/下拉拿不到数据**。

> 对照：正确读 `res.rows` 的 13 个页面（门店/预约/券/聚合订单/C端用户/操作日志…）全部正常渲染，证明这 6 处是偏差，不是约定问题。
> **为什么没早发现**：admin Playwright/E2E 套件此前从不存在，本轮是**首次对 admin 真跑 UI + 真数据**。

### 清单（均为 1 行修复）

| # | 文件:行 | 现状 | 应改为 | 严重度 | 现象 |
|---|---|---|---|---|---|
| B-1 | `plus-ui/src/views/gz-pay/transaction/list.vue:167` | `list.value = res.data ?? []` | `list.value = res.rows ?? []` | 🟠 可见 | 7 笔支付订单 → 列表"暂无数据"（footer 却显示共7条） |
| B-2 | `plus-ui/src/views/gz-recycle/appointment/index.vue:217` | `list.value = res.data ?? []` | `list.value = res.rows ?? []` | 🟠 可见 | 1 笔回收预约 → "暂无数据" |
| B-3 | `plus-ui/src/views/gz-recycle/price-rule/index.vue:206-208` | `const { data } = await listGzRecyclePriceRule(query); list.value = data.rows` | `const res = await listGzRecyclePriceRule(query); list.value = res.rows; total.value = res.total` | 🟠 可见 | 4 条价目 → "暂无价目规则" + 控制台 `Cannot read properties of undefined (reading 'rows')` |
| B-4 | `plus-ui/src/views/gz-common/admin-user/index.vue:291` | `((resp as any) || []).map(...)` | `((resp as any)?.data || []).map(...)` | 🟡 可见 | 新增管理员弹窗"关联门店"下拉恒空（门店 options API 实返 `{data:[...]}`），控制台 `(resp || []).map is not a function` |
| B-5 | `plus-ui/src/views/gz-pay/refund/index.vue:115` | `list.value = res.data ?? []` | `list.value = res.rows ?? []` | 🟡 潜伏 | 当前 0 退款不显形；**首笔退款发生即列表恒空** |
| B-6 | `plus-ui/src/views/gz-pay/payout/index.vue:111` | `list.value = res.data ?? []` | `list.value = res.rows ?? []` | 🟡 潜伏 | 当前 0 打款不显形；**首笔反向打款发生即列表恒空** |

### 附带 i18n 缺陷（B-4 同页发现）
