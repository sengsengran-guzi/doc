## T2 · 拼豆预约（核心，mp 用户 + 店员核销）

| # | 入口/操作 | 预期 |
|---|---|---|
| T2.1 | tabbar「拼豆」→ 进选座页 | 门店默认成都（隐藏切换）；选日期 |
| T2.2 | 选日期后看座位区 | **每个座位类型 × 时段显余量**「还剩 N 个单人座」/「已满」灰显（**不能是全空白**） |
| T2.3 | 选 1 个座位类型 + 1 个时段 | 金额 = 该类型单价（单笔，无累加） |
| T2.4 | 选优惠券（T0.4 发的券） | 列出 unused + 适用拼豆 + 未过期；选中后**实付 = 单笔金额 − 券面额**（下限 0） |
| T2.5 | 📱 提交前采集：手机号空 → `getPhoneNumber`；微信号空 → 填微信号 | 两者都采集成功才能提交；拒绝授权 → 拦截提示 |
| T2.6 | 提交 → 拉起支付（mock）→ 用 T0.6 驱动到账 | 跳预约详情 |
| T2.7 | 预约详情页 | **座位栏显「四人桌」等类型名（不空白）** + 金额区(原价/抵扣/实付) + 支付状态 + 核销码二维码 |
| T2.8 | 未付单的详情（提交后未驱动到账时看） | QR **不亮可扫**，显「待支付」遮罩（已付才亮彩色码） |
| T2.9 | 「我的」→ 我的预约（bean/my-list） | 列表卡座位栏显类型名（不空白）；状态正确 |
| T2.10 | 我的预约 → 取消一笔 pending 单 | 取消成功，配额释放 |
| T2.11 | 📱🔑 店员核销：店员 mp「我的」→门店管理→**核销**（verify-scan）→ 扫顾客核销码 | 扫已付 pending 单 → 核销成功（状态→已核销）；扫未付单 → 被拒「未支付」 |
| T2.12 | 🔑 admin 退款：支付→退款，对一笔已付拼豆单全额退款 → 回 mp 看 | 退款后该单 mp 显已退款；**配额释放**（该类型×时段名额恢复，不被占用）；已用券不退还（保守口径） |
| T2.13 | 余量边界 | 把某档约到最后一个 → 该档转「已满」灰显 |

## T3 · 回收预约（mp 用户 + 店员核对 + mock 反向打款）

| # | 入口/操作 | 预期 |
|---|---|---|
| T3.1 | tabbar「回收」→ 填单页 | 填品类 + 数量 + 描述（可多条） |
| T3.2 | 📱 上传实物照片 | **必填**，不传无法提交 |
| T3.3 | 填完看估价 | 实时显**预估金额 + 预计时长**（各品类按自身数量命中价目表累加）；超价目区间 → 「到店面议」提示 |
| T3.4 | 📱 选时段 + 采手机/微信号 → 提交 | 提交成功，状态「待到店核对」(submitted) |
| T3.5 | 「我的」→ 回收记录（recycle/my-list） | 列表显状态（含打款态）；**断网/异常时显「加载失败，点此重试」（不能静默显「暂无记录」）** |
| T3.6 | 📱🔑 店员核对：店员 mp「我的」→门店管理→**回收核对**（staff-verify）→ 输预约号调出 | 看到用户提交的照片 + 物品清单 + 估价 |
| T3.7 | 📱 店员拍照 + 微调最终金额 + 确认 | 确认成功 → 触发 mock 反向打款 |
| T3.8 | 店员微调金额填一个**离谱大值**（如估价 50 元填 50000） | **被拦截**「超出允许上限」（≤估价×3 且 ≤¥1000，资金安全） |
| T3.9 | 确认后回收单状态 | confirmed_onsite → paying → （mock 查单）→ **paid 已到账**；用户「我的回收记录」同步显已到账 |
| T3.10 | 🔑 admin：回收→反向打款单管理 | 看到打款单状态；失败可重试（重试成功后回收单也收敛 paid，不卡死） |
