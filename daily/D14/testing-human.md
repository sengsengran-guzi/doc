## 1. RECYCLE-002 回收填单 + 自动估价（「回收」tab，N=1 可达）

**入口**：底部「回收」tab → 回收填单页。

| # | 步骤 | 预期 | ✅/❌ |
|---|---|---|---|
| 1 | 进回收 tab | 报头 + 填单区（品类 + 数量 + 描述，可加多条） | ⬜ |
| 2 | 选品类（字典 gz_recycle_category）+ 填数量 | 品类下拉 = 卡牌/谷子；填数量 | ⬜ |
| 3 | 实时估价 | 命中价目表 → 显「预估 ¥X」+「预计 N 分钟」；多品类累加（如 card×3 + goods×5 = ¥30 / 35 分钟） | ⬜ |
| 4 | 超区间品类 | 填不支持品类/数量 → 提示「该品类暂不支持线上估价，到店面议」，不阻断其余 | ⬜ |
| 5 | **上传实物照片（必填）** | 「上传实物照片」拍/选图 → 上传成功显缩略图；**未传照不可提交**（CTA 灰显 + 提示「请先拍照上传实物」） | ⬜ |
| 6 | 选到店时段 | 按匹配时长展示可约时段 → 选日期 + 时段 | ⬜ |
| 7 | 采手机号 | 未绑 → getPhoneNumber 原生授权 → 绑定后显脱敏号 | ⬜ |
| 8 | 填微信号 | 未填 → input 填 → 保存 | ⬜ |
| 9 | 提交（齐全才可点） | 提交成功 → 回收记录显新单 status「待到店核对」+ 预约号 RCY-… | ⬜ |
| 10 | C 设计系统遵循 | 粗墨边 / 朱红 / 硬投影 / 报头风 / 不混 emoji | ⬜ |

**微信原生能力**（真机必验）：chooseMedia 拍照上传 COS + getPhoneNumber 授权。

## 2. RECYCLE-003 店员核对 + 触发反向打款（mp 店员端，N=2 可达）

**前置**：① 先用普通用户走完 §1 产生一个 `submitted` 预约；② 店员账号（gz_user 绑 sys_user，授 `gz:recycle:appointment:verify`）登 mp。
**入口**：店员账号 →「我的」→「门店管理」区 →「回收核对」。

| # | 步骤 | 预期 | ✅/❌ |
|---|---|---|---|
| 1 | 店员登 mp →「我的」 | 显「门店管理」区（普通用户不可见）+「回收核对」入口 | ⬜ |
| 2 | 进回收核对 → 调出预约 | 按预约号/列表调出 submitted 单：见**用户提交的实物照片** + 物品清单 + 预估金额 | ⬜ |
| 3 | 店员拍照存证 | 拍实物照 → verify_image_ids 上传成功 | ⬜ |
| 4 | 微调最终金额 | final_amount 默认 = 预估，可改（如实物品相微调） | ⬜ |
| 5 | 确认无误 | 确认 → status「店员已确认」（confirmed_onsite）→ 自动触发反向打款 | ⬜ |
| 6 | mock 打款到账 | 状态推进 打款中（paying）→（查单 ≤2min）→ **已到账（paid）** | ⬜ |
| 7 | 留痕核验（admin 兼可） | admin 回收预约单详情：两套照片 + 核对人 verified_by + verify_time + 实付金额 | ⬜ |
| 8 | 停用即踢（ADR-0004） | owner 在 admin 停用/解绑该店员 sys_user → mp 再点回收核对即 401/403 | ⬜ |

**微信原生能力**：chooseMedia 店员拍照；真实「商家转账到零钱」= mock（真实权限待甲方，到账文案以 mock 闭环为准）。
