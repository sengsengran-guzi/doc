# ADR-0024 拼豆「小程序能不能订」收敛（四套机制 → 桌型一律进目录 + 一个计数）

- **状态**：已决 + 已实现（§4 迁移 `V202609261629` 已在 dev 真 apply；§3 于 2026-09-26 按 Kevin 返工定稿：面板→抽屉、逐时段 + 全天两个入口、去掉「今天不上小程序」；§6 定稿：长期关闭是「今天关闭」的默认值、可被当天覆盖）
- **日期**：2026-09-26
- **关联**：ADR-0016（下单选桌型 + 核销现场分座）／ADR-0018 §2 §3（加座并桌 / 排位）／ADR-0023（临时桌双轴，**本 ADR 取代其 §1 的双轴模型，保留其 §2「过滤只加在小程序可订面」**）／doc/11 §3.4 §3.10
- **取代**：ADR-0023 §1「`enabled` 与 `mp_visible` 是两个正交轴」

## 背景

甲方 2026-09-26 反馈（kevin-test.xlsx，`ACC-ef7f85ca` + `ACC-6e6df26c`）：

> 「admin 里不要临时桌，现在的逻辑做的有点复杂，店员很难操作；我们梳理一下，店员创建桌子后，可对桌子或者座位进行开关操作，如果关闭，则小程序上不可预订，但是无论是否关闭，看板功能都不应该受影响。**这里的启用功能可以去掉**，改成上述描述的开关」
>
> 「红框区域，添加一个板块，动态显示小程序看板日期里没有被预订的座位，同时加一个按钮，可以动态让该座位不在小程序上预订」

**注意这不是新需求，而是 ADR-0023 同一诉求的第二次提出**（8/26 原话：「你别改我设置好的小程序桌子」「我们开了新桌子，他们店员就只能写纸条了，后台看板是没有的」）。ADR-0023 把能力做出来了，但 UI 上摊成 **两轴 + 二选一「用途」** 而显得复杂，于是甲方要求「去掉启用、换成一个开关」。

## 现状：控制「小程序能不能订」竟有四套并存机制

| # | 机制 | 入口 | 关掉的效果 | 看板 | 实际使用情况 |
|---|---|---|---|---|---|
| 1 | `gz_bean_seat_type_config.enabled` | 桌型配置「启用」列 | mp 不可订 | 也消失 | **dev 全库 `enabled=0` 零行** —— 纯理论概念 |
| 2 | `gz_bean_seat_type_config.mp_visible` | 桌型配置「用途=临时桌」 | mp 不可订 | **不受影响** | **dev 库里存活行 0 条**（`mp_visible=0` 的 id=8~18 全是 E2E 残留且已软删）。保留它的理由是**代码路径**而非现存数据：ADR-0018 加座并桌、以及「加座座位可改号」判定（`GzBeanSeatServiceImpl` 的 `mp_visible=0 + book_mode=whole`）都依赖它 |
| 3 | `gz_bean_seat.enabled` | 座位单元「启用」列 | **分座时硬拒 `SEAT_DISABLED`** | **受影响** | **dev 真实座位 `enabled=0` 零行** |
| 4 | `gz_bean_slot_quota_close.close_count` | 「实时余量与关闭」 | 某天某小时格**少卖 N 个** | 不受影响 | 在用 |

甲方反对的正是 **#1 的"一关全没"** 与 **#3 的"关座位连带挡住分座"**。

## 决策 §1：座位级开关**不做**（mp 顾客不按座位售卖）

`slotCapacity(config)` 全文为 `quantity × capacity`（`seat` 模式）或 `quantity`（`whole` 模式），**从不读座位表**；mp 余量 = `max(0, slotCapacity − quotaClose)`。座位行只服务看板分座与渲染。

mp 顾客端 UI 也不展示具体座位（ADR-0016：只选桌型档 + 数量 + 时段，提交只回传 `seatTypeConfigId`，座位由店员核销时现场分配；`seat-map` 接口如今只剩店员扫码核销页 `verify-scan.vue` 在用）。

→ **座位级开关对"顾客能不能订"零影响**（顾客压根没有座位可选），它唯一的作用面是**店员分座候选**。而"关一个座就把新客分不过去"正是甲方反对的"影响看板/日常操作"。

**甲方真实诉求 = 「预留几个座位，方便线下来人时机动调整」**（Kevin 2026-09-26 澄清）。它在顾客侧**唯一可落地的形式是减该桌型的档位配额**：预留 N 个座 ⇒ mp 该桌型每格少卖 N 个。也就是 `slot_quota_close`（数量制），不是另一个座位级开关。

**「座位坏了」的口径**：直接**删该座位**（`gz_bean_seat` 软删 `del_flag='1'`）—— 原 ADR-0018 §3 指定的 `seat.enabled=0` 随本轮删列退场，不复原、也不新增替代开关。

## 决策 §2：桌型一律进小程序；「少卖几个」只由计数表达

| 机制 | 处置 | 说明 |
|---|---|---|
| `seat_type_config.enabled` | **删列** | 与 `mp_visible` 在 mp 侧语义完全重复；"退役"语义本就等于软删。`resolveConfigs`（座位批量生成）改用 `del_flag` 过滤 |
| `seat_type_config.mp_visible` | **字段保留，UI 入口摘掉** | 见下方「关于 mp_visible」 |
| `seat.enabled` | **删列** | 对顾客侧无效果（§1），唯一效果是挡店员分座（甲方反对）→ 删。「座坏了」改走删座位 |
| `slot_quota_close.close_count` | **保留** | 唯一能表达"今天这格少卖几个"的机制。看板抽屉可就地逐时段 / 全天调整 |

**关于 `mp_visible`（2026-09-26 Kevin 选 A）**——这一条我第一版做错了，留档：

- 它 = ADR-0023 的**临时桌**：`mp_visible=0` 的桌型**整个不进小程序目录**（`selectTypeSlotAvailability` / `selectDaySellable` 都按 `mp_visible=1` 过滤）。
- 第一版我只把「用途」radio 换成 `el-switch` 并改叫「对小程序开放」，**机制原样保留** —— 但甲方 8/26 原话第一句就是「**admin 里不要临时桌**…这里的启用功能可以去掉」，9/26 又重申「真正对小程序不可见的应该是**座位**，而不是整个桌型」。**是没执行到位，不是理解分歧。**
- 第二版（当前）：**编辑弹窗里的开关、列表里的筛选下拉、独立列全部摘掉** → 桌型一律进小程序，不可能再从 UI 把整档关掉。「今天少卖几个」只由 `slot_quota_close` 表达。
- **字段保留、默认 1**，理由：① 删列要新迁移且不可逆；② `isTempSeatType` 放宽（ADR-0018「线上单可分到临时桌」的跨型分座放行）先留着不拆，将来真需要临时桌还能把入口加回来。
- **可见性兜底**：既然入口没了，就不该有人能造出 `mp_visible=0` 的行；万一有人直接改库，座位类型列表会在类型名后就地挂一个「未开放」角标 —— 否则那张桌子会同时从小程序和看板「今日可售」里静默消失，没人看得出来。

**不变量（新模型）**：
1. `mp_visible`（现存唯一用途）**只影响小程序可订面**，看板 / 分座 / walk-in / 排位 / 改派 / 放座 / 延时**一律不受影响**（沿用 ADR-0023 §2 的 6 加 / 8 不加清单）。admin 已无入口改写它。
2. 「退役一个桌型」= 删除（软删），不再有 `enabled` 这种"半存在"态；「座位坏了」同理 = 删该座位。
3. mp 可订量恒 = `max(0, slotCapacity(config) − quotaClose(store, config, date, slot))`。
4. 要"今天留几个座"= 看板「今日可售」抽屉里调（或「实时余量与关闭」页）；要"这桌不做了"= **删掉该桌型**（不是关开关）。

## 决策 §3：看板「今日可售」抽屉（甲方 8/26 红框位；2026-09-26 按 Kevin 返工定稿）

入口 = 看板统计条那一行里、**和五个统计格同规格的第 6 个格子**，文案「**今日小程序剩余座位**」，点击开 **el-drawer**。（甲方 2026-09-26 两轮：原来挤在「过期待处理 / 刷新」行右侧的小链接太不显眼 → 挪到下面；但第一版做成独占整行的大按钮又「太夸张了」→ 定稿为与统计格同行等高、`type="primary" plain` 的可点格子。）抽屉 = 只读可售信息 + 就地改配额，**不是新的可订性模型**：

- **桌型行**（只含 `mp_visible=1`）：桌型名 + 订法标签 / 每格可订（带单位，whole→「桌」seat→「座」）/ 今日已订(单) / 空闲座位数 / 今日关闭（各格一致给值，不一致显「分时段」）。
- **展开**：当天没被预订的座位（座位号 + 桌号），供店员判断线下来人能接几桌。
- **逐时段余量表**（展开区内每桌型一张）：`时段 / 已订 / 剩余 / 今日关闭 / 本时段留几个` + 行内 stepper 与「保存」——**逐格**改 `close_count`。
- **按天统一**：行内 stepper（列头「全天都留几个」）+ 按钮文案随 stepper 变：「全天都留 N 个」（N=0 时显示「恢复全开」）+ 提示「上限 {cap} {unit}」= 对该桌型该日每个小时格统一覆盖同一个值。
  **文案硬要求**（Kevin 2026-09-26 返工）：必须让店员一眼看出"这是关几个座位/桌"，不能只说"按天统一 / 应用到全天"。
- **点蒙层即关**：本抽屉**不得**写 `:close-on-click-modal="false"`（甲方 2026-09-26 明确要求所有抽屉/弹框点蒙层自动关闭，`ACC-f1265c3c`）。E2E 有回归守卫。

**两个写动作都落在同一张表**：逐时段走 `POST /system/gz/bean/slotQuotaClose`（单格 upsert），按天统一走 `POST /system/gz/bean/slotQuotaClose/close-day`（逐格循环 upsert，`@Transactional` 全成或全回滚）。

**明确不做「今天不上小程序」**（甲方 2026-09-26 明确不要整档关停）：要关满就把该格 `closeCount` 调到上限 `capPerSlot`，效果等价但不是一个独立概念。

**冻结的接口契约**：

```
GET  /system/gz/bean/booking/day-sellable?storeId=&sessDate=      perm gz:bean:booking:verify
  → R<List<{ seatTypeConfigId, name, bookMode, capPerSlot, slotCount, activeBookings,
             slots: [{ slotStart, slotEnd, booked, closeCount, remaining }],
             freeSeats: [{ seatId, seatNo, tableNo }] }[]>
     只含「对小程序开放」的桌型；slots 长度 = slotCount（按格起整点升序），
     remaining = max(0, capPerSlot − closeCount − booked)
     各格关闭数是否一致由前端从 slots 推，不下发汇总字段（单一真源 = slots）
     activeBookings 是**按 config 去重**的当日活跃单量（跨格单只算 1，不是逐格求和）

POST /system/gz/bean/slotQuotaClose                              perm gz:bean:slotQuota:edit
  body { storeId, seatTypeConfigId, sessDate, slotStart, closeCount, remark? }
  语义 = 覆盖该桌型该日**该一个**小时格的 close_count（0 = 该格全开）

POST /system/gz/bean/slotQuotaClose/close-day                     perm gz:bean:slotQuota:edit
  body { storeId, seatTypeConfigId, sessDate, closeCount, remark? }
  语义 = 把该桌型该日**每一个小时格**的 close_count 统一覆盖为 closeCount（0 = 恢复全开）
  校验 = 门店存在 / 桌型属本店 / 桌型对小程序开放 / 0 ≤ closeCount ≤ slotCapacity(config)
  → R<{ slotCount, closeCount, cap }>
```

**关键不变量（防"两个计数器错配"复发）**：逐个写动作与逐个读动作用的小时格集合**必须**同源 —— 即共用 `GzBeanHourSlotResolver.selectEnabledSlotsForDate` + `sliceWindowsToHourSlots`，**不得各自算一份**。否则会出现"关掉的格"与"mp/看板读余量的格"不是同一批，正是 GZ-BEAN-055 消灭过的那类缺陷。

**为什么是数量制而不是座位制**（ADR-0018 §3 客户 7.05 定，2026-09-26 复核维持）：`whole` 模式的配额单位是「桌」（单人 = N 张单人桌），按物理座位数折算会量纲错配 —— 历史事故就是"拿座数减配额 → 单人被压成约满"。数量制在两种 `book_mode` 下都自洽，且与 mp 顾客侧看到的东西一一对应。

## 决策 §4：数据迁移（一次性，append-only）

新迁移（`V<当下时间戳>__GZ-BEAN-056-seat-enabled-collapse.sql`）三步，语义等价、不丢业务态：

```sql
-- 1. 桌型 enabled=0（原语义「退役：看板/生成/walk-in 全部消失」）→ 等价软删
UPDATE gz_bean_seat_type_config SET del_flag='1' WHERE enabled=0 AND del_flag='0';
-- 2. 座位 enabled=0（原语义仅「挡分座」）→ 新模型无对应物；按甲方口径「关闭座仍可被分给新客」不动 del_flag

-- 3. 删列
ALTER TABLE gz_bean_seat_type_config DROP COLUMN enabled;
ALTER TABLE gz_bean_seat DROP COLUMN enabled;
```

两张表都是小表（config ~18 行 / seat ~66 行），ALTER 重建代价可忽略。

## 决策 §6：长期关闭 = 今日默认（可覆盖）+ 文案口径 + 下线「实时余量与关闭」页（Kevin 2026-09-26 第三、四轮反馈）

### §6.1 文案：一律说「关闭 N 个」，不说「留 N 个」

第一版写「今天留 N 个」是想表达"给线下留几个、不给线上"（甲方原话「预留几个座位」）。但「留」在中文里**两读**：
「给线上留 N 个」与「留出 N 个不给线上」正好相反。Kevin 看图后第一反应就是"逻辑反了"。

**定稿**：口径一律用「**关闭**」——列头「全天关闭几个」/「本时段关闭几个」，按钮「全天关闭 N 个」（N=0 →「恢复全开」）。
数值语义不变：`closeCount = N` 表示**从每格可订量里减掉 N 个**。E2E 加了守卫：抽屉里不得再出现「留 N 个」。

### §6.2 长期关闭 = 「今天关闭」的**默认值**（覆盖关系，不是相加）

第二版做成了 `有效可订量 = 总容量 − 长期关闭 − 当日关闭`（两个减项相加）—— **错**。Kevin 2026-09-26 澄清的
真实口径是：

```
今日生效关闭数 = 当日该格已记录值（可空）
                 可空  → 沿用「长期关闭」（今天没设，就按这个数关）
                 有值  → 用当天的值（含显式 0 = 今天全开），只对今天生效
有效可订量     = 总容量 − 今日生效关闭数（下限 0）
```

即甲方原话：「如果今天店员不填写，那就默认是长期关闭几个；然后在打开的抽屉里直接显示，比如 2；
但是店员随时可以调整，比如改成 0 或者 3 都可以，但是店员在看板抽屉里的调整只对今天有效。」

**`null` 与 `0` 必须分开**（这是整个改动最容易做错的地方）：

| 当日记录 | 含义 | 生效关闭数 |
|---|---|---|
| 没有行（`null`） | 今天没设 → 照常按长期默认关 | 长期关闭数 |
| `close_count = 0` | 今天**特意全开**（把长期默认顶掉） | 0 |
| `close_count = N` | 今天改成关 N 个 | N |

所以读当日值必须用 `IGzBeanSlotQuotaCloseService.getQuotaCloseOrNull`（回 `Integer`，可空），
**不能用归 0 的版本** —— 会把"今天没设"误判成"今天显式全开"，长期默认直接失效。

**上界也跟着改回总容量**：当日关闭是绝对值覆盖，不是叠加在长期之上的增量 —— 店员今天完全可以把长期关着的
那几个也一起关满（传总容量）或全放开（传 0）。同理，**包天名额上界回到 `slotCapacity`**：拿一个"默认值"
去永久卡包天名额会出现「今天明明全开、包天名额却被压住」的假约束。

**看板抽屉要能看懂**（Kevin：「让店员能清晰理解」）：

| 列 | 含义 |
|---|---|
| 每格容量 | 桌型总容量（不扣任何关闭） |
| 长期关闭(默认) | 桌型配置里的默认值。**说明放在列头**（每行都一样，不该在每行重复一个 ⓘ）＋ 图标放大一档、hover 变色 |
| 今天关闭 | **今日生效值** + 角标「沿用长期」/「今天已改」/「分时段」 |
| 全天关闭几个 | stepper 预填今日生效值，上限 = 总容量；按钮「全天关闭 N 个」/「今天全开」 |

逐时段表同理：每行「今天关闭」显示生效值 + 是否沿用，stepper 预填生效值。

**桌型配置列表另加一列「小程序可约数量」**（甲方 2026-09-26）：`总容量 − 长期关闭`，单位随 `book_mode`
（whole=桌 / seat=座），列头带同一个说明 tooltip —— 店员在配置页就能看到「这个桌型今天小程序上能约几个」，
不用跑去看看板。派生字段 `GzBeanSeatTypeConfigVO.mpSellableCapacity`，在 `fillDerived` 里算（复用
`expectedCells(...)` 的容量规则，不另写一份乘法）。

  店员写关闭会全线 403（本项目撞过一次同类号事故）。所以只删页面，权限行保留。
- 后端 `GET /availability/detail` 保留（暂无前端入口；只读、零维护成本，脚本/排查还能用）。

## 决策 §7：价格配置集中到「星期 × 时段价格」弹窗（GZ-BEAN-058，甲方 2026-09-26）

### §7.1 问题

价格散在两个弹窗里：**编辑座位类型**有「基础单价 / 包天基础价」，**星期 × 时段价格**有逐格价与按星期价，
而后者只是把前两者当 **placeholder** 显示。店员要改价得先想清楚"这个价属于哪一层"，还得来回切弹窗。

### §7.2 定稿

**所有价格只在一个入口改**：列表操作列的「星期 × 时段价格」弹窗。

- 弹窗顶部新增「**全局默认价**」区块：`基础单价(元/小时)` + `包天基础价(元/天)`（包天未开放时不显示后者）。
  它俩本来就是网格里留空格子的**回退值**（第 3 级兜底 / 包天兜底），放在这里最自然。
- 网格里留空的单元格仍是"回退到全局默认"，说明文案改成指向上面的区块。
- **编辑座位类型**弹窗里两个价格输入**撤掉**，只留一行**只读**的「价格设置」指路：
  「当前基础单价 ¥…/小时、包天基础价 ¥…/天。价格（含逐格 / 按星期）统一在列表的「星期 × 时段价格」里改。」
  （不留输入框 —— 两处都能改 = 改完不知道哪边生效。）
- 新增桌型时两个价落 **0**，随后去价格弹窗设；列表里 `基础单价 = 0` 会**红字 + tooltip** 报警
  （忘了设价 = 小程序按 ¥0 计价，这条是那次改动唯一新增的踩坑面，用可见性兜住）。

### §7.3 新增一个专用写入口（**不要**复用全量编辑接口）

`PUT /system/gz/bean/seatTypeConfig/default-price` + `GzBeanSeatTypeConfigPriceBo{id, priceCent, dayPassPriceCent}`
（perm `gz:bean:seatTypeConfig:edit`）。

**为什么必须单独开一个**：全量编辑走 `toEntity(bo)` 的**逐字段拷贝**，缺省字段会被写成默认值
（`dayPassQuota→0`、`mpVisible→1`、`mpLongCloseCount→0`、`name→null`）—— 只想改个价，却把包天名额、
长期关闭、可见性一起清掉。新端点只建「id + 两个价」的补丁实体，MP `updateStrategy=NOT_NULL` 保证
其余列不进 `SET`。真机验证过：改价后 包天名额 / 长期关闭 / mp 可约 / 订法 / 数量 全部原样。

前端同理：**编辑**桌型时 payload **不带**这两个价（否则会拿表单里的旧值把价格弹窗刚改的价覆盖回去）；
只有**新增**才传 0。

## 被否决的方案

- **B. 保留座位级开关**：死控件（见 §1），否决。
- **E. 连 `mp_visible` 字段一起删**（2026-09-26 Kevin 未选）：最彻底、与甲方话完全对齐，但不可逆（要加回得再新建迁移），且会把 `isTempSeatType` 连带拆掉。选 A 是"先摘入口、留退路"。
