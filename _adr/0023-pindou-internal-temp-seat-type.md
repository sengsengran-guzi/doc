# ADR-0023 拼豆临时桌型（`enabled` × `mp_visible` 正交）

- **状态**：已决（已实施 D22 / GZ-BEAN-054）
- **日期**：2026-08-26
- **关联**：ADR-0016（下单选桌型 + 核销现场分座）／ ADR-0014（去字典自定义桌型 + 整桌/按座双模式）／ ADR-0017（包天）／ ADR-0018 §2（排位）／ doc/11 §3.4

## 背景

甲方 2026-08-26 微信原话：

> 「现在后台看板 无法计时 就3*4的计时板 我们4*4了」「周末会开四个四人桌」「平时要看具体情况」「看板上加上 不用就不填就行了」
> 「加的人 看板没法看时间 只能写纸条 就不方便」「先加一个1*4吧」「后续再加都有可能」
> 「**你别改我设置好的 小程序桌子**」「加后台看板」「**小程序就是只开放 2\*4**」
> 「我意思是 客人 上桌了 我们后台的桌子 四人桌的计时桌子 后台计时 只有12位 3\*4对吧 我们开了新桌子 他们店员就只能写纸条了 后台看板是没有的」
> Kevin：「你的意思就是搞几个临时桌子在看板里，不进入小程序」→ 甲方：「**对的**」「**临时桌子 主要功能一样就行了 编号啥的都可以自己写**」

**根因**：`gz_bean_seat_type_config.enabled` 是唯一开关，且**四处耦合** —— mp `type-slots` / 看板 `selectBoard` / 座位批量生成 `resolveConfigs` / walk-in 校验。停用一个桌型 = 小程序不显示 **且** 看板上该桌型座位全部消失。系统缺少「只对小程序隐藏、看板照常」的能力。

## 决策 §1：`enabled` 与 `mp_visible` 是两个正交轴

新增 `gz_bean_seat_type_config.mp_visible TINYINT NOT NULL DEFAULT 1`。

| `enabled` | `mp_visible` | 语义 |
|---|---|---|
| 1 | 1 | 正常桌型（**存量全部**，DEFAULT 1 保证零行为变化） |
| 1 | 0 | **临时桌**：看板有格 + 可 walk-in 计时 + 可承接线上单现场分座；小程序不展示不可订 |
| 0 | * | 退役：看板 / 座位生成 / walk-in 全部消失（语义完全不变） |

**两轴正交必须写死在这里**，否则半年后有人会把它们合并回去。`enabled` = 是否存在；`mp_visible` = 对哪个渠道开放。

**命名取 `mp_visible` 而不是 `is_temp`**：不变量只有「不进小程序」。`is_temp` 承诺了一个不存在的时间语义（会自动过期？周末才有效？），将来甲方真要「临时桌到期自动隐藏」时那个名字已被占用成布尔开关，反而挡路。**UI 上仍叫「临时桌」**（甲方的词），DB / API 用机制名。

甲方「不用就不填就行了」= 临时桌平时保持 `enabled=1` 空着（看板上几个 idle 格），不需要每周切开关。

## 决策 §2：过滤只加在「小程序可订面」

**加过滤（6 处）**：`selectTypeSlotAvailability`（mp 桌型目录唯一源头，最关键）／ `selectDayPassOptions` ／ `selectSeatMap`（防临时桌编号外泄）／ `submitPaid` / `submitPaidGroup` / `submitDayPass`（竞态兜底，复用 `SEAT_TYPE_DISABLED=4013`，mp 已有分支）。

**绝对不加**：`selectBoard`（**功能本体**）／ `walkInCreate`（临时桌的主用法，它故意不过桌型配额闸）／ `adminCreateBooking` ／ 座位批量生成 ／ 核销分座 / 排位 / 改派 / 放座 / 延时 ／ 座位 CRUD ／ admin 桌型 list·listByStore·detail ／ mp 我的预约与详情（按 booking 快照渲染，历史单必须能显示桌型名）。

**两个判断项**：

- **实时余量表加过滤排除临时桌**。这张表的语义是「小程序可订多少 / 关几个不让订」，配额关闭直接扣 mp 可订量；而临时桌不进 mp、walk-in 又故意绕过配额闸 → 给它摆一个关闭 stepper 就是**拨了不生效的假开关**，纯新增 bug 面。同步在 `GzBeanSlotQuotaCloseServiceImpl.upsert` 加防呆。
- **营业额聚合不加过滤**。临时桌上的现金 walk-in 是**真钱**，过滤掉才是对账事故。口径影响仅为拆分表多一个类目行（周中为 0、周末突起是正常形状）。配套在桌型表单加 hint：「营业额报表按桌型名拆分，请用可读名称」。

**优惠券 / 前 N 名免费促销不改**：券只在 `submitPaid` 生效（已被拦住）；免费促销按 `store + is_free` 计数与 config 无关。但**交付说明须写明**：店员在临时桌勾「免费」的 walk-in 单**照常吃掉当期免费名额**（既有行为，非本次引入）。

## 决策 §3：放开线上单分座到临时桌（受控例外）

桌型匹配闸共 **5 处**（3 处服务端强校验 `assignSeatAtVerify` / `preAssignSeat` / 改派 helper + 2 处候选座查询），全部从「同桌型」放宽为「**同桌型 ∪ 本店 `mp_visible=0` 的临时桌**」。

这是对「桌型严格匹配」这条既有决策的**受控例外**。代码里那条注释（「客人 mp 买双人桌、实际坐三个四人桌游玩，钱一样不退款让其游玩；桌型/座位对不上无法 assignSeatAtVerify」）说明严格是有意的；临时桌之所以能例外，是因为**它本来就没有线上对应**，是周末溢出客的物理承接位。

**booking 自身的 `seat_type_config_id` / `seat_type_snapshot` 保持不变** —— 钱仍算在客人买的桌型上，营业额口径完全不受影响。候选座返回时正常桌型在前、临时桌垫底（店员的肌肉记忆是「先看正常桌」，周末加桌不能把原有顺序挤位）。

**连带修掉一个会被这次放开激活的潜伏 bug**：`toBoardRow`（放座/延时/改派后的单行刷新）原本取的是 **booking 的**桌型档，而 `selectBoard` 取的是**座位的**。改造前两者恒等所以没暴露；跨桌型分座后会分叉，导致单行刷新把该座位归进错误分组（甚至凭空多出一个分组）。已统一为**座位视角** —— 看板上 `seatTypeConfigId` / `typeName` / `bookMode` / `mpVisible` 都是座位维度字段。

## 决策 §4：`batchGenerate` 返回结构升级

`upsertSeatUnit` 命中已存在的正常座会**幂等跳过并返回 0**，而 `seat_no` 是**全店唯一**（`uk_tenant_store_seat_no`）。店员给临时桌填了一个与正式桌撞车的前缀时，旧接口只回一个 `0` → 前端提示「生成 0 个」→ 店员看到的是「点了但什么都没多」，完全不知道是前缀撞了。

临时桌是**高频新建对象**（周末加桌），且 `derivePrefix` 对纯中文名恒回退 `"X"`，多建两个必撞 —— 踩中概率很高。

返回值升为 `{created, skipped, conflictSeatNos, hasConflict}`。关键是区分**同桌型跳过**（正常的幂等重跑，不该报警）与**跨桌型跳过**（真·前缀冲突，必须提示换前缀）。

## 拒绝的替代方案

| 方案 | 结论 |
|---|---|
| 不加字段，靠 `enabled` + 命名约定（名字前缀「临时-」，mp 按前缀过滤） | **否决**。① `enabled=0` 会让座位从看板消失，正是甲方要的东西没了；② 靠名字过滤是把业务规则塞进用户可编辑的自由文本，改个名就崩；③ 会污染 `enabled=0` 的正当用途（退役旧桌型保留历史） |
| `quantity=0` 让 mp 恒显「已满」 | **否决**。mp 会**显示**该桌型（灰满态）而不是隐藏；且 `generateForConfig` 对 `quantity<=0` 直接 skip → 看板也没有格。两头都错 |
| 标记放在 `gz_bean_seat`（座位级） | **否决**。mp 的下单维度是桌型档（ADR-0016，mp 根本不显示座位），座位级标记无法阻止 mp 展示该桌型；且看板 / walk-in 都按 config 分组渲染 |
| 纯前端「自绘格子 / 本地便签」 | **否决**。甲方明确要**计时**（「加的人 看板没法看时间」），计时必须落 booking → 必须有真实 seat 行 → 必须有 config |
| 给看板加「显示停用桌型」总开关 | **否决**。语义混淆（停用 ≠ 内部），且开关是全局的：真正退役的旧桌型会一起冒出来 |

一个布尔列 + 6 处 mp 面过滤 + 1 个表单项 + 1 个看板 tag，是最小可行改动，且**存量零行为变化**。这个功能没有更便宜的正确解。

## 坑位

1. **`GzBeanSeatTypeConfigServiceImpl.toEntity` 是手写字段拷贝**，不会自动带新字段 —— 漏改会让老客户端/老脚本提交时静默把桌型藏起来。空值一律视作 1，与 DB DEFAULT 同口径。
2. **临时桌与包天互斥**：包天是纯 mp 概念，配了就是一组永远读不到的死数据，还会让 `validateDayPass` 的上界校验产生误导性报错。入口直接拒（`validateMpVisible`），mp `day-pass-options` 再兜一道防历史脏数据。
3. **切换已有桌型为临时桌不做级联清理**：已有的未来线上单不受影响，仍在看板、仍可核销。前端切换时弹静态确认说明这一点。
4. `derivePrefix` 对纯中文名回退 `"X"` —— 临时桌大概率是中文名，默认前缀恒为 `X`。admin 的「一键生成计时格」prompt 默认值给 `T`+序号绕开，不动后端。
