# ADR-0005 C1 跨境物流由「7 节点」简化为「2 态 + 终态」及合同对齐

- 日期：2026-06-03
- 状态：**Accepted**
- 决策人：Kevin（C1 决策 2026-05-26 已拍板；合同对齐选项 2026-06-03 拍板）
- 关联：合同 §2.1（含 formal 签字版）/ §2.3 / PRD M5 跨境物流 / doc/02 / doc/10 §业务流 / doc/11 字段表 / doc/12 UI 索引 / USER-103 / USER-104 / ADMIN-104 / 落地批次 D08-D11

## Context

原始口径（**合同 + PRD + 设计三处一致**）写的是「跨境物流 **7 节点**状态展示」：

- **合同 §2.1**（含已签字 formal 版）：首版范围列「跨境物流 7 节点状态展示」。
- **合同 §2.3**：约束「跨境物流**不自动抓取轨迹**，仅展示甲方手动推进的节点」+「国内物流仅展示甲方录入单号，用户自查」。
- **PRD M5**：跨境物流模块按 7 节点设计状态机。
- **index / doc 早期索引 §3.4**：同写 7 节点状态展示。

C1 决策（Kevin 2026-05-26 业务评审）认为 7 节点对甲方运营是过度负担——甲方每单要手动点 7 次状态，绝大多数节点用户无感知价值，真正有用的信息只有「货还在日本 / 已到国内派送中（带国内单号）/ 已签收」三态。遂决定**简化为 2 态 + 终态**。

由此产生与 formal 合同文本的**措辞不一致**（合同写 7 节点，实现做 2 态），需在本 ADR 里固化"实现取舍"与"合同对齐姿态"两件事。

## Decision

### 1. 实现：2 态 + 终态（独立并行字段，不覆盖业务状态）

物流状态 `logistics_status` 取值收敛为：

| 取值 | 含义 | 进入条件 |
|---|---|---|
| `in_japan` | 货在日本（备货 / 集运 / 待发） | 默认初始态 |
| `in_china_dispatching` | 已到国内派送中 | **必录** `cn_carrier_code`（走字典 `gz_express_carrier` 9 项：yto/sf/zto/yunda/jd/ems/debang/jitu/other）+ `cn_tracking_no` |
| `delivered` | 已签收（终态） | 甲方手动确认 |

- `logistics_status` **独立于 `business_status` 并行**，两者互不覆盖。
- admin 端形态 = **订单详情手动切换状态 + 录国内单号**（不是批次推进 / 不自动归集）。
- 物流审计复用 `gz_logistics_audit`。

### 2. 合同对齐姿态（Kevin 2026-06-03 拍板选项）

采用 **「先做 2 态、验收前与甲方口头确认、事后补签合同 §2.1」**：

- 本次**不改 formal 合同文本**（不动签字版 §2.1 的"7 节点"措辞）。
- V1.1 验收前，由 Kevin 与甲方**口头确认**「物流展示简化为 2 态 + 终态」并取得认可。
- 事后**补签合同 §2.1**（书面追认简化口径），将文本与实现拉齐。

## Rationale

- **用户视角扁平化更省甲方运营**：甲方每单只需在「到国内派送」一步录国内单号 + 签收时点一次终态，远低于 7 次手动推进；用户拿到的有效信息不减（国内单号自查物流轨迹）。
- **仍满足合同原意**：合同 §2.3 的两条核心约束——「甲方手动推进」「国内单号用户自查」——在 2 态方案下**完全保留**；「不自动抓取物流轨迹」(§2.3) 不变。简化的只是"展示粒度"，不是"能力缩水"。
- **不改 formal 文本的取舍**：改签字合同流程重、需双方走签字；而口头确认 + 事后补签既守住了合规追认，又不阻塞 V1.1 实施进度。

## Consequences

- ✅ `doc/02`（PRD）/ `doc/10`（业务流）/ `doc/11`（字段表）/ `doc/12`（UI 索引）+ **USER-103 / USER-104 / ADMIN-104** 已统一对齐 2 态 + 终态口径。
- ✅ **禁止项固化**（违反直接打回）：7 节点 / `logistics_node` 字段 / `gz_logistics_node` 表 / 批次推进 / 自动归集 `GROUP BY` / `gz_express_company`（用 `gz_express_carrier` 字典）/ 物流时间线色 / tokens 1.5。
- ⚠️ **残留风险**：验收时甲方可据 formal 合同 §2.1「7 节点」措辞主张原始口径。缓释 = 验收前口头确认 + 事后补签 §2.1；本项**列为 PRD v1.0 / 验收沟通的甲方确认项**，Kevin 在验收会议纪要中留痕。
- ⚠️ 合同文本与实现在补签完成前存在**短暂措辞 gap**：仅在"已口头确认、未补签"窗口期内；该窗口由 Kevin 控制，验收即推动补签关闭。

## 拍板结论（Kevin）

1. **实现 = 2 态 + 终态**（`in_japan` / `in_china_dispatching` / `delivered`），进派送态必录 `cn_carrier_code` + `cn_tracking_no`，admin 订单详情手动切换。（C1，2026-05-26）
2. **合同对齐 = 先做 2 态、验收前口头确认、事后补签 §2.1**，本次不改 formal 文本。（2026-06-03）
3. **残留风险列为甲方验收确认项**，纪要留痕，补签关闭 gap。
