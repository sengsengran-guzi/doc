## 1. 前提与实测

- **官方路线全部走不通**：A1 甲方拿煤炉官方合作、A2 接入已有官方合作代购商（楽一番 / 任意门 等），2026-10-01 均确认失败。只剩自建直连。
- **读数据现在可行**（2026-10-01，东京 Sakura 机房 IP，匿名、不登录、共 9 次请求）：

  | 项 | 结果 |
  |---|---|
  | mercapi 0.5.0 搜索「ブルーロック 缶バッジ」 | ✅ 首次 4.0s（含建连）/ 之后 1.4s、2.4s，每页约 120 条 |
  | 商品详情 | ✅ 0.31s，含价格 / 在售状态 / 运费承担 `送料込み(出品者負担)` / 成色 / 图片 |
  | 原图下载 | ✅ 1.2s / 90KB |
  | 无头 Chromium 搜索页 / 商品页 | ✅ 8.5s（118 个商品）/ 3.5s（「購入手続きへ」按钮正常渲染） |

  只说明「现在、小流量、不登录」能用，**不代表不会被封**。
- **写（下单）未验证**：需要甲方账号，放在 D7 技术验证做。
- **规约**：煤炉明文禁止「用官方界面以外的方式访问服务」与逆向工程，处罚是取消交易 / 限制使用（封号）。甲方已知悉并选择接受，上线前补书面确认。

## 2. 架构

```
 miniapp-jp ──HTTPS──▶ ruoyi（阿里云，国内）─────HTTPS+HMAC，同步调用────▶ mercari-gateway（阿里云东京，Python）
   搜索 / 详情           用户 · 地址 · 订单 · 支付 · 退款                     搜索 / 详情：网页版 JSON 接口，失效降级无头浏览器
   立即购买 / 付款       报价锁价 · 孤品锁 · 准入 · 过滤 · 翻译               下单：Playwright 常驻登录态 → 固定日本 ISP 出口 → 煤炉
   订单状态              下单任务 · 三态结果 · 对账 · 风控熔断                 按订单号幂等 · 购买记录对账 · 交易巡检 · 心跳
                         人工代买 · 交易跟踪 · 验货 · 本地调度                 图片代理（阿里云 CDN 备案域名回源）
 admin（plus-ui）──────▶ 代切下单 / 账号 / 配置 / 词表 / 履约看板
```

三条不变量（ADR-0025）：

1. **钱只在 ruoyi**。日本服务没有用户个人信息，只认「订单号、商品 ID、锁定日元价」。
2. **结果不明不动钱**。只有拿到煤炉交易号算成功；点购买之前就发现已售出 / 下架 / 涨价算失败；其余一律「不明」→ 三次对账 → 转人工。
   对账只会自动得出「成功」，查不到一律转人工、不自动退款。不明状态下绝不再次下单。
3. **遇验证即停**。验证码 / 登录验证 / 连续失败 → 停号、关自动下单总开关、全部转人工；不打码、不伪装指纹、不批量注册。

## 3. 主链路

| 段 | 权威 | 一句话 |
|---|---|---|
| 找货 | `FLOW:F-JP-05` | 中文 → 词表 → 阿里云机翻 → 实时搜（3 分钟缓存 + 合并请求）→ 白名单 / 黑名单 → 标题机翻 |
| 报价下单 | `FLOW:F-JP-06` | 详情实时查 → 准入三态 → 报价 10 分钟 → 立即购买（一单一件）→ 孤品锁 → 付款 → 回调写任务 |
| 自动下单 | `FLOW:F-JP-07` | 按账号串行 → 45s 同步调用 → success / failed / unknown → 对账 → 风控熔断 |
| 人工代买 | `FLOW:F-JP-08` | 准入转人工 / 对账不清 / 暂停期间 → 日本员工填结果；到付多退少不补 |
| 交易跟踪 | `FLOW:F-JP-09` | 巡检（卖家取消自动退）→ 到仓 → 验货 → 手工评价 → 接回一期履约看板 |
| 一期缺口 | `FLOW:F-JP-10` | 未付款 15 分钟关单（释放孤品锁）· 退款卡单 10 分钟补偿 |
| 运营 | `FLOW:F-JP-11` | 定价 / 过滤 / 准入 / 交易参数 · 中国银行汇率 30 分钟一抓 · 心跳 · 10 分钟主动探测 |

## 4. 计划（任务 D7–D15，串行，每个任务末一道干净 QA 门）

27 个 ticket，明细与每个任务的 QA 范围见 [phase-plan.md](phase-plan.md)。

| 任务 | 主题 | 粗估 | 门 |
|---|---|---|---|
| **D7** | 支付通道堵洞（过期即不可付 · 迟到付款不被吞）+ 一期缺口（未付款关单 · 退款补偿）+ 数据底座（5 表 · 两表 ALTER · 字典 · 配置 · 实体 · 状态机） | 3.5d | 拼豆 / 回收 / 拼团支付与一期全量回归不红 |
| **D8** | 日本服务骨架（新仓 · Docker · HMAC · 健康检查 · fake 驱动）+ 只读接口（搜索 · 详情 · 图片代理 · 降级） | 2.5d | 只读契约测试 |
| **D9** | ruoyi 找货与下单前半（客户端 · 心跳 / 探测 · 归一化 · 翻译 · 过滤 · 准入 · 汇率 · 报价 · 提交订单 · 孤品锁 · 回调写任务） | 3.5d | 孤品锁真并发 |
| **D10** | ruoyi 下单引擎（调度 · 三态 · 对账 · 熔断 · 人工代买 · 运费差价 · 交易跟踪 · 履约守卫），对 fake 驱动 | 3.5d | ★ 故障注入：断网 / 超时 / 重启下零重复下单、零错误退款 |
| **D11** | admin 五页（代切下单 · 账号与总开关 · 配置 · 词表 · 履约看板代切行） | 3d | Playwright E2E |
| **D12** | mp 四页（tabbar 三格 + 搜索 · 详情 · 下单确认 snap 模式 + 协议 · 订单代切状态） | 3.5d | 模拟器 E2E |
| **D13** | 技术验证 go / no-go（东京服务器 + ISP 代理 + 甲方账号） | 2–3d | ★ 结论写进 ADR-0025 §3 |
| **D14** | 日本服务真下单 + 真对账 / 巡检 | 3d | no-go 时关闭 |
| **D15** | 联调与全链路演练 R1–R8 | 1.5d | 演练剧本全绿 |

合计约 26 人日（不含甲方侧等待：账号、服务器与代理、转运仓、CDN 备案域名、书面确认）。

**为什么技术验证不排第一**：它要等甲方的账号、东京服务器和 ISP 代理，排第一会让整期干等。日本服务提供 fake 驱动，
ruoyi 侧的下单引擎、admin、mp 都能先对着它做完；D13 只依赖 D8，**账号一到就插队提前跑**，只有 D14 等它的结论。
no-go 时 D14 关闭、自动下单总开关永久关闭、全部走人工代买，D7–D12 的产出不受影响。
**为什么一期缺口放 D7**：代切把「没抢到就退款」变成主路径、「未付款占着孤品」变成阻塞，这两个缺口不补，代切跑不起来。

## 5. 风险与上线卡点

| 风险 | 级别 | 应对 |
|---|---|---|
| 采购账号被封 | 高 | 甲方书面接受（REQ-SNAP-062）；遇验证即停、全转人工；每日上限 + 冷却；人工代买始终可用 |
| 煤炉改版致读 / 写失效 | 中，一年多次 | 10 分钟主动探测 + 自动切人工；修复工时属持续性成本 |
| 小程序内出现违规图片 | 高（整个小程序被处罚） | 分类白名单 + 关键词黑名单在 ruoyi 侧执行，不信任日本服务 |
| 跨境链路晚高峰抖动 | 中 | 搜索 3s 熔断 + 缓存兜底；下单不受影响（异步 + 对账）；D7 晚高峰实测 |
| 退款频次升高 | 中 | 退款补偿任务（D8）；高退款比例对商户号风控的影响请甲方向微信支付确认 |
| 人工代买积压 | 中 | admin 角标 + 评价期限置顶；暂停自动下单时日本员工工作量会突增 |

**上线卡点**（进 `GO-LIVE-CHECKLIST.md` 桶 2）：甲方书面确认封号风险 · 采购账号 + 付款方式 + 余额 · 转运仓地址设为账号默认地址 · 图片 CDN 备案域名 · 定价三参数初值 · 代切协议条款文案过目 · 拼团一期本身的上线卡点（ICP / 类目 / 商户号绑定）。
