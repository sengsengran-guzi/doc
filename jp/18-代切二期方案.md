## 1. 前提与实测

- **官方路线全部走不通**：A1 甲方拿煤炉官方合作、A2 接入已有官方合作代购商（楽一番 / 任意门 等），2026-10-01 均确认失败。只剩自建直连。
- **读数据现在可行**（2026-10-01，东京 Sakura 机房 IP，匿名、不登录、共 9 次请求）：

  | 项 | 结果 |
  |---|---|
  | mercapi 0.5.0 搜索「ブルーロック 缶バッジ」 | ✅ 首次 4.0s（含建连）/ 之后 1.4s、2.4s，每页约 120 条 |
  | 商品详情 | ✅ 0.31s，含价格 / 在售状态 / 运费承担 `送料込み(出品者負担)` / 成色 / 图片 |
  | 原图下载 | ✅ 1.2s / 90KB |
  | 无头 Chromium 搜索页 / 商品页 | ✅ 8.5s（118 个商品）/ 3.5s（「購入手続きへ」按钮正常渲染） |

  只说明「现在、小流量、不登录」能用，**不代表不会被封**。
- **写（下单）未验证**：需要甲方账号，放在 D7 技术验证做。
- **规约**：煤炉明文禁止「用官方界面以外的方式访问服务」与逆向工程，处罚是取消交易 / 限制使用（封号）。甲方已知悉并选择接受，上线前补书面确认。

## 2. 架构

```
 miniapp-jp ──HTTPS──▶ ruoyi（阿里云，国内）─────HTTPS+HMAC，同步调用────▶ mercari-gateway（阿里云东京，Python）
   搜索 / 详情           用户 · 地址 · 订单 · 支付 · 退款                     搜索 / 详情：网页版 JSON 接口，失效降级无头浏览器
   立即购买 / 付款       报价锁价 · 孤品锁 · 准入 · 过滤 · 翻译               下单：Playwright 常驻登录态 → 固定日本 ISP 出口 → 煤炉
   订单状态              下单任务 · 三态结果 · 对账 · 风控熔断                 按订单号幂等 · 购买记录对账 · 交易巡检 · 心跳
                         人工代买 · 交易跟踪 · 验货 · 本地调度                 图片代理（阿里云 CDN 备案域名回源）
 admin（plus-ui）──────▶ 代切下单 / 账号 / 配置 / 词表 / 履约看板
```

三条不变量（ADR-0025）：

1. **钱只在 ruoyi**。日本服务没有用户个人信息，只认「订单号、商品 ID、锁定日元价」。
2. **结果不明不动钱**。只有拿到煤炉交易号算成功；明确已售出 / 下架 / 涨价算失败；其余一律「不明」→ 三次对账 → 转人工。不明状态下绝不再次下单。
3. **遇验证即停**。验证码 / 登录验证 / 连续失败 → 停号、关自动下单总开关、全部转人工；不打码、不伪装指纹、不批量注册。

| 段 | 权威 | 一句话 |
|---|---|---|

## 4. 计划（任务 D7–D13，串行，每个任务末一道干净 QA 门）

| 任务 | 主题 | 内容 | 粗估 | 门 |
|---|---|---|---|---|
| **D7** | 技术验证（go / no-go） | 东京服务器 + 固定 ISP 出口 + 甲方账号：读接口限速、网页版下单全流程（买一件 ¥300 级商品）、下单耗时、验证出现频率、登录态保持时长、购买记录可查 | 2–3d | ★ 结论写进 ADR-0025 §3；no-go → 自动下单降级全人工，D9 只做读 + 巡检 |

| **D11** | admin | 代切下单页 · 账号页 · 配置页 · 词表页 · 履约看板代切行 | 3d | Playwright E2E |

| **D13** | 联调与全链路演练 | 真机：搜 → 付 1 分钱级商品 → 1 分钟内看到结果（REQ-SNAP-038）· 人工代买 · 卖家取消 · 验货不通过 · 风控熔断恢复 | 1.5d | 演练剧本全绿 |

合计约 24 人日（不含甲方侧等待：账号、转运仓、CDN 备案域名、书面确认）。

**为什么 D7 排第一**：自动下单能不能在甲方账号上跑通，决定 D9 / D10 一半的工作量。先花 2–3 天验证，比做完再发现跑不通便宜得多。
**为什么一期缺口放 D8**：代切把「没抢到就退款」变成主路径、「未付款占着孤品」变成阻塞，这两个缺口不补，代切跑不起来。

## 5. 风险与上线卡点

| 风险 | 级别 | 应对 |
|---|---|---|
| 采购账号被封 | 高 | 甲方书面接受（REQ-SNAP-062）；遇验证即停、全转人工；每日上限 + 冷却；人工代买始终可用 |
| 煤炉改版致读 / 写失效 | 中，一年多次 | 10 分钟主动探测 + 自动切人工；修复工时属持续性成本 |
| 小程序内出现违规图片 | 高（整个小程序被处罚） | 分类白名单 + 关键词黑名单在 ruoyi 侧执行，不信任日本服务 |
| 跨境链路晚高峰抖动 | 中 | 搜索 3s 熔断 + 缓存兜底；下单不受影响（异步 + 对账）；D7 晚高峰实测 |
| 退款频次升高 | 中 | 退款补偿任务（D8）；高退款比例对商户号风控的影响请甲方向微信支付确认 |
| 人工代买积压 | 中 | admin 角标 + 评价期限置顶；暂停自动下单时日本员工工作量会突增 |

**上线卡点**（进 `GO-LIVE-CHECKLIST.md` 桶 2）：甲方书面确认封号风险 · 采购账号 + 付款方式 + 余额 · 转运仓地址设为账号默认地址 · 图片 CDN 备案域名 · 定价三参数初值 · 代切协议条款文案过目 · 拼团一期本身的上线卡点（ICP / 类目 / 商户号绑定）。
