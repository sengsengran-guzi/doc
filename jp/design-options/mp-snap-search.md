# 设计方案 · mp 代切搜索（含入口位置）

> 蓝图锚点：`UI:mp.snap_search` · `UI:mp.home.snap_entry` · `REQ-SNAP-003` / `012` / `013`
> 产出方式：HTML 草案 [snap-review.html](snap-review.html)（「代切搜索」tab）· 端：mp
> 状态：✅ **已选定 2026-10-03 · 方案 B**

**真正要拍的点**：代切入口放在哪。结果页本身（输入框 + 两列网格 + 排序）三个方案一致，差别只在客人怎么进来。

| 方案 | 一句话定位 | 关键差异 | 取舍 |
|---|---|---|---|
| **A** | 首页搜索框 | 首页顶部加一个搜索框，点进独立搜索页；tabbar 不动（首页 / 我的） | 强：改动最小，首页仍以拼团场为主；弱：搜索框挂在场列表上，客人会以为是「搜场」，代切这门生意不显眼 |
| **B** | tabbar 新增「煤炉」 | tabbar 变三格（首页 / 煤炉 / 我的），煤炉 tab 就是搜索页：空态放热门词（词表里的作品名）+ 贴链接提示 | 强：两门生意分得清（首页 = 拼团，煤炉 = 代切），一级入口最贴甲方「增加粘性」的目的；弱：tabbar 图标要新做一套，空态需要热门词撑场 |
| **C** | 首页搜索框 + 热搜卡片 | A 的基础上，首页场列表下方加一排「煤炉热搜」横滑卡片（按热门词预取真实商品） | 强：首页有代切的真实货引流；弱：**首页每次打开都要调日本服务**，日本服务慢或挂了会拖累首页，与「拼团不受代切影响」的原则冲突 |

**AI 推荐**：**B**。

理由：代切和拼团是两种找货方式——拼团是「看店员上架了什么」，代切是「我要找某样东西」。
把代切放进首页搜索框（A），等于让一个页面承担两种找货心智；C 则让首页的可用性依赖日本服务。
B 的代价只是一套 tabbar 图标和一个热门词空态，热门词直接取词表 `term_type=ip` 的前若干条，不新增配置。

**Kevin 选定**：**方案 B（tabbar 三格：首页 = 拼团 / 煤炉 = 代切搜索 / 我的）**
**Kevin 反馈**：
> 先问清「拼团和代切有什么区别」（拼团 = 甲方员工手工上架的官方新品、逛场批量买；代切 = 客人自己搜煤炉二手孤品、付款即抢），明白后选 B，分成两个 tab。（2026-10-03 设计门）
