# 设计方案 · admin 代切下单（人工代买队列 + 交易跟踪）

> 蓝图锚点：`UI:admin.snap_purchase` · `UI:admin.fulfill_board.snap` · `REQ-SNAP-031` / `033` / `034`
> 产出方式：HTML 草案 [snap-review.html](snap-review.html)（「代切下单」tab）· 端：admin（走 ruoyi / Element Plus 默认审美，只拍组织方式）
> 状态：✅ **已选定 2026-10-03 · 方案 A**

**真正要拍的点**：日本员工的工作台怎么组织。他每天要做三件事：处理人工代买、跟进已买到的交易（到仓 / 验货 / 评价）、
偶尔看自动下单有没有卡住。这三件事和店员在国内用的履约看板（按客人聚合、批量推进发货）是两拨人、两种节奏。

| 方案 | 一句话定位 | 关键差异 | 取舍 |
|---|---|---|---|
| **A** | 独立页 · 三个 tab | 新菜单「代切下单」：顶部状态条（自动下单开关 / 暂停原因 / 账号健康）+ 三个 tab：待人工（N）/ 交易跟踪 / 自动任务；每个 tab 是一张 el-table + 行内操作 | 强：完全照 ruoyi 范式，开发最快；日本员工只看这一页；弱：交易跟踪里各阶段混在一张表，要靠状态筛选 |
| **B** | 独立页 · 泳道看板 | 同样是新菜单，主体换成横向泳道：待人工 / 待卖家发货 / 已发货 / 已到仓待验货 / 待评价，每张卡片带操作按钮 | 强：一眼看出每个阶段堆了多少单；弱：Element Plus 没有现成看板组件，要自研；单量一多卡片墙难扫 |
| **C** | 并进现有履约看板 | 不新开页，在履约看板加「代切」来源筛选和代切专属列 / 操作 | 强：只有一个页面；弱：履约看板按客人聚合、为批量发货设计，人工代买需要按付款时间排队——两种排序冲突，日本员工会被国内发货的行淹没 |

**AI 推荐**：**A**。

理由：日本员工和国内店员是两拨人，C 把两种节奏塞进一页；B 的可视化收益不抵自研看板的成本。
A 的「交易跟踪」tab 默认按评价期限升序、期限 12h 内的行标红置顶，阶段堆积用 tab 上的数字角标表达，够用。

**Kevin 选定**：**方案 A（独立页 · 待人工 / 交易跟踪 / 自动任务三个 tab）**
