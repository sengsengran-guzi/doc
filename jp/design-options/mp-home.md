# 设计方案 · mp 首页

> 蓝图锚点：`UI:mp.home` · `FLOW:F-JP-02.step1`
> 产出方式：ASCII 结构对比 · 端：mp
> 状态：**已选定 2026-08-05**

| 方案 | 一句话定位 | 关键差异 | 取舍 |
|---|---|---|---|
| **A** | 裸场列表 | tabbar 第一格直接就是场列表，无其他模块 | 强：一期极简，场本身就是内容，不需要再包一层；弱：没有运营位，也没有订单快捷入口 |
| **B** | 聚合首页 | 轮播 banner + 进行中的场 + 我的订单快捷入口 | 强：像完整电商首页，有运营位可用；弱：一期无运营内容，banner 容易是空的；多 0.5-1 天 |

**方案 A 结构**
```
┌─ tabbar: 首页 | 我的 ─────┐
│ 【进行中】                │
│ [封面] 8月夏日限定场       │
│        8/1 - 8/10        │
│ [封面] 秋叶原扫货场        │
│        8/3 - 8/12        │
│ 【即将开始】              │
│ [封面] 中元祭特场          │
└──────────────────────────┘
```

**方案 B 结构**
```
┌─ tabbar: 首页 | 我的 ─────┐
│ ◀ [轮播 banner] ▶         │
│                           │
│ 进行中的场                 │
│ [封面] 8月夏日限定场       │
│ [封面] 秋叶原扫货场        │
│                           │
│ ┌─ 我的订单 ──── 待收货 3 ┐│
│ └────────────────────────┘│
└──────────────────────────┘
```

**AI 推荐**：A —— 一期没有运营内容，banner 会是空的或占位图，反而不如直接给场。

**Kevin 选定**：**方案 B（聚合首页）**
**Kevin 反馈**：
> 选 B，首页做聚合。（2026-08-05 AskUserQuestion 拍板，推翻了 AI 推荐的 A）

## 选定后的落地约束

- **banner 无配置时降级为单张默认图**，绝不显示空轮播或占位骨架 —— 这是选 B 的主要风险，必须防住
- banner 走 `sys_config` 后台可配（沿用现有 miniapp 的 `gz.home.banners` 形态）
- 订单入口带待收货款数角标
- 场区块分「进行中 / 即将开始 / 已结束」三组，进行中置顶
